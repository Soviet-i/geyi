# REQ-411 平衡扫描（2026-10-28）

## 方法

- 工具：`tools/geyi_balance_scan.c` + `tools/geyi_balance.c`（C，复用 `gy_game` 规则核心）。
- 出招策略：**工具内基线贪心**，只按即时金币、己方/敌方士兵血量做一步打分，
  **不是 AI 模块**；不能把结果当成“AI 棋力”或最终平衡结论。
- 参数网格：20 组（棋盘 4~8 × 4 组生成间隔/血量/攻击/费用/奖励组合），见源代码表。
- 种子：固定公式 `20261028 + group*100000 + game*7919`；同一二进制重复运行逐字节一致。
- 每局最多 2000 回合；未分胜负计为 draw。

## 结果

### TC-408 标准扫描：20 组 × 50 局

```bash
python tools/balance_scan.py --groups 20 --games 50 \
  --out evidence/balance/20261028/balance_scan.csv
```

- 结果：两次运行 CSV 完全一致，PASS。
- 文件：`balance_scan.csv`，SHA-256
  `46b0031fe212ac51c5a6bd161f950c1c7a2402527d94d2119ed90f89279c6912`。
- 汇总：红胜 574、蓝胜 391、平局 35（红 57.4%）。
- 50 局下红胜率 ≥72% 的组：3、15、16、19。

### 扩展扫描：20 组 × 500 局（降低抽样噪声）

```bash
python tools/balance_scan.py --groups 20 --games 500 \
  --out evidence/balance/20261028/balance_scan_500.csv
```

- 结果：两次运行 CSV 完全一致，PASS。
- 文件：`balance_scan_500.csv`，SHA-256
  `a06fd6b583526c76ac0583293b09275b6b9676c9f95e4a574041f15b51608bcf`。
- 汇总：红胜 5688、蓝胜 4084、平局 228（红 56.9%）。
- 500 局下仍 ≥72% 的组只有 15（7×7、间隔 5、血量 6、攻击 1、费用 3，红 73.8%）
  和 19（8×8、同规则，红 77.8%）；50 局时的组 3、16 回落，说明 50 局的极端值
  有较大抽样误差，不能直接当平衡结论。

## 结论与限制

- 在该**基线贪心**策略下，红方总体略占优（500 局 56.9%），低血量/低攻击/低费用的
  7~8 棋盘组红方优势更明显；这只说明参数组合值得进一步用 AI 对局复核。
- 没有使用 `gy_ai`，不能据此宣称 AI 平衡、棋力或最终产品平衡。
- 未测人类玩家、未测真实板端耗时；后续应固定更强 AI 策略、增加种子/局数，
  并对组 15/19 做重点人工试玩。
- 复现命令与 CSV 已入库；任何代码/参数网格/种子变化都会改变 CSV，需重新生成并更新哈希。
