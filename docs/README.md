## 文档维护规则

1. 先改需求（`01`），再改设计（`02`），再改测试计划（`03`），执行后写报告（`04`）。
2. 新增 REQ/TC 必须能互相追踪；`python scripts/check_trace.py` 必须 PASS。
3. 关键决策写 ADR，并在 `02` 决策表与 `manifest.yaml` 引用。
4. 历史段落保留，但要在节首标明“历史”；当前结论放顶部总表。
5. 不伪造测试数据/提交时间/证据；本期范围外的强化验证写“扩展项”，材料缺口写“可补证”，历史记录保留原状态词。
