## 遇到的问题与解决

1. **直接 rebase 会撞几十处冲突**：团队 `geyi_ui.c` 从 13KB 长到 85KB，还多了 `geyi_ai`、`geyi_net_*`、`geyi_config`。
   解法是从最新 develop 新建分支、只搬该搬的模块，而不是把旧分支硬 rebase 上去。
2. **MSVC 找不到**：团队 `run_host.py` 只查 `ProgramFiles\Microsoft Visual Studio\2022`，而本机在 `E:\Virsual Studio\chanpin`。
   `build_desktop.py` 已支持 `VS_ROOT`，于是给 `run_host.py` 也加了 `VS_ROOT` 兜底（与团队既有约定一致，不引入新变量）。
3. **MSVC 把 `history_reset_confirm` 判成重定义**：C 语言里先调用后定义会先生成隐式 `int` 声明，再看到 `static void` 定义就冲突。
   解决：在文件顶部补原型声明。
4. **`test_net.c` 在 MSVC /W4 /WX 下报 C4245/C4456**：这是团队既有代码在 MSVC 下的警告，不是本次改动；
   本机 `run_host.py` 因此跑到 net 用例就中断，我改用单独编译命令验证 `geyi-history-tests`（61 断言 PASS）。
   CI 用 Ubuntu gcc，不受影响，但值得跟团队提一句。
5. **存储口径冲突**：团队文档 REQ-603/ADR-0010 写的是 RAM 版、重启清空；组长 11-11 要求 NOR + flashdb KV。
   本轮按 RAM 版交付（能合并优先），flashdb 需要 FAL 分区和板端验证，已写进 `docs/04` 的差异说明。
