# 单机规则原型使用说明

负责人：殷白玉。状态：个人原型，暂定规则待组长试玩确认，不是最终游戏。

## 运行

已构建的电脑版本：双击根目录play-single.cmd。仅有字符棋盘，不是LVGL界面。
重新编译运行：`python tools/run_host.py --play`，需要MSVC或通过CC指定gcc/clang。
试玩窗口打开时，可用`python tools/run_host.py --verify`在独立目录复测，避免覆盖占用的exe。
src/geyi_game.c为真实C核心，电脑程序没有另写一套Python规则。

| 输入 | 意义 |
|---|---|
| w 1 / d 1 / s 1 / a 1 | 上右下左预览，选择1名可行动士兵；数字可改为2等 |
| ok | 执行刚才的预览；棋盘改变才消耗回合 |
| cancel | 丢弃预览，不改变真实状态 |
| place 0 | 在己方底线第0列放兵，直接确认；列从0到5 |
| resign | 当前行动方认输 |
| restart | 使用相同种子重开 |
| quit | 关闭电脑程序 |

如果该方向无可行动士兵，允许数量0，仅移动数字；有可行动士兵时不能用0绕过选择。
R/B后的数字是士兵血量，单独的数字是数字块。每次均显示CURRENT STATE；PREVIEW ONLY不是已执行。
先输入w 1，再cancel，棋盘应不变；再输入w 1和ok，应换为蓝方。试完反馈规则是否符合预期。

## 第一版边界

默认6×6、血量8攻击2、放兵4金币、合并奖励1、击杀敌兵奖励2；数字先、士兵后。
数字伤害发生在压缩与合并完成后。数字达到65536后不再合并，金币上限1000000，防止数值溢出。
可行动友兵链按方向从前往后处理，但未选中的前兵不会自动移动。
指示点暂用边中心，数量键盘输入；未实现角度/滞回、放置模式的倾斜选列、音效、LVGL、AI或蓝牙。
预览为调试用途显示完整候选后状态，包括下一随机数字；正式UI应隐藏未来随机信息。
预览结构只供同一可信进程使用，不可把它当作蓝牙输入直接提交；联机应提交行动意图由房主重算。
API当前单线程调用，gy_selftest为启动专用、不可并发重入。
板端仍是RGB例程加核心自检，烧录它不会出现游戏棋盘。本轮没有烧录或硬件验证。

## 代码理解顺序

1. 看geyi_game.h：状态、行动、预览，区分谁保存真实局面。
2. 看gy_preview：在副本上算下一局面，无效操作不修改原状态。
3. 看numbers和finish：滑动合并、伤害、统一清除死亡和判胜负。
4. 看gy_commit：原状态不一致就拒绝旧预览，防止重复确认。
5. 用test_geyi.c中的固定棋盘预测结果，再运行验证。
