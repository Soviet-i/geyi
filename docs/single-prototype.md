# 单机规则原型使用说明

## 移动顺序修正（REQ-303/REQ-304，2026-10-18）

移动现在按倾斜方向从目的边到另一端逐格处理，数字块和选中士兵交错移动：
前面的士兵/数字先动，后面的棋子轮到时看到的是更新后的棋盘。数字块不再整批
先于士兵移动；被数字临时挡住的士兵可以在数字让开后移动。可移动数量也按同样
的前到后遍历模拟，被临时挡住的士兵会计入可移动数。伤害在全部移动后按数字块
前方相邻士兵结算；士兵攻击仍是一步一攻击、无反击，死亡单位到回合结束才移除，
本回合仍阻挡后方单位。

固定试玩局面：
- 数字2在(1,1)、士兵在(3,1)，向右：数字应到(3,1)，士兵到(4,1)。
- 一行 `N2 B8 N2 . B8 .`，向右选2个士兵：两个士兵都应移动，数字补到各士兵后方
  并造成伤害，结果类似 `. N2 B6 . N2 B6`。

## 人机对战试玩（REQ-315，待板端验证）

模式页现在只有一个“人机对战”入口，点击后进入准备页：
- 左侧红色方框表示先手，默认“玩家”；右侧蓝色方框表示后手，默认“AI”；
- 点击任一方框在“玩家/AI”之间互换先后手，红蓝颜色不变；
- “取消”返回模式页；“开始游戏”按当前选择进入新局，AI 执红时先手。

AI 回合会显示“AI 思考中...”，期间倾斜、确认、放兵和格子点击都不执行；
AI 决定动作后会先显示约 500ms 的预览（与人类倾斜/放兵预览相同），然后自动
确认一次并回到人类回合。预览期间仍不能操作；返回首页或重开会取消搜索或
预览，不会在离开后落子。
AI 使用 negamax + Alpha-Beta，默认迭代加深最多 5 层、300ms 上限；搜索不读取
真实 RNG、不生成新数字块，避免偷看随机结果。

电脑端：`python tools/build_desktop.py` 重建，双击生成的
`build/desktop/geyi-desktop-cn.exe`；主机搜索较快，仍不代表开发板耗时。
主机剪枝对比可运行 `build/host/geyi-ai-bench.exe --depth 4` 和
`--depth 4 --no-pruning`，节点数/分数见 `evidence/ai/ai_bench.log`。

开发板：烧录后串口应出现 `[geyi:selftest] ai=PASS`。试玩时重点观察：
AI 是否自动走子、AI 回合人类操作是否无效、思考期间屏幕是否还能刷新、
主页/重开能否取消、单次思考是否可接受、屏幕新增汉字是否缺字。请回传视频
或串口日志及照片；未收到证据前不能把主机结果写成真机通过。

已知限制：评估权重为初始值，未做平衡性调参；搜索不建模每步随机块；
自定义搜索深度页未实现；当前规则仍是个人原型暂定规则。

## 板端首次验证

本轮用户选择B一次集成显示/触摸/IMU/按键。完整固件准备后，双击flash-geyi-board.cmd，
确认板型sf32lb52-lchspi-ulp、关闭其他串口终端，输入FLASH执行烧录并自动采集120秒日志。
此操作替换板内固件，保留电脑文件；启动先屏幕向上平放约1秒，不按键不晃动。
工具匹配唯一CH340、校验源码未晚于固件，并记录二进制及源码哈希；不凭COM9固定假设。

1. 拍屏幕和终端，核对lcd READY、core/input PASS、WHO_AM_I=6a及calibrated。
2. 先用触摸方向→取消，再方向→确认，检查只有确认才换手。
3. 回中，向屏幕上/右/下/左依次倾斜，观察预览；每次回中后重试。
4. 选好方向后KEY1短按确认，应只走一步。KEY1是电源复用键，不做长按测试。
5. KEY2在预览时取消、空闲时进入放置；金币足够时左右倾斜选底线列再KEY1短按确认。
6. 反馈屏幕裁切、方向颠倒、无预览、重复走棋等问题，保留原始日志，不重复盲目烧录。

证据自动存evidence/board/时间目录。当前IMU方向映射沿用外设台公式，仍须真机确认，
字体/自动选兵规则未优化，声音与蓝牙未启用。编译成功不表示以上六步通过。

## 图形版优先试玩

双击项目根目录`play-graphical.cmd`，打开本地LVGL窗口，无需开发板或网络。
鼠标点击方向按钮，使用加减选择数量，绿色边框表示预览发生变化的位置；点击“確認”才执行。
“取消”丢弃预览，“放置”在金币足够时选择己方底线空格再确认，“重開”按同种子重开。

方向键或WASD也能选择方向，Enter/空格确认，Esc取消。窗口使用SDK现有中文字体，部分文字为繁体。

请先尝试：点击上 → 观察高亮 → 点击取消，确认棋局不变；再次点击上 → 点击确认，观察换手。
再用加号选2名士兵、重开、认输。放置需先通过合并或击杀获得至少4金币，不提供作弊金币。
如果选定方向可行动兵少于所选数量，实际选择会收敛到可行动数；没有可行动兵时可只移动数字。

## 运行

已构建的电脑版本：双击根目录play-single.cmd。仅有字符棋盘，不是LVGL界面。
重新编译运行：`python tools/run_host.py --play`，需要MSVC或通过CC指定gcc/clang。
试玩窗口打开时，可用`python tools/run_host.py --verify`在独立目录复测，避免覆盖占用的exe。
src/geyi_game.c为真实C核心，电脑程序没有另写一套Python规则。

| 输入 | 意义 |
|---|---|
| w 1 / d 1 / s 1 / a 1 | 上右下左预览，选择1名可行动士兵；数字可改为2等 |
| ok | 执行刚才的预览；棋盘改变才消耗回合 |
| cancel | 丢弃预览，不改变真实状态 |
| place 0 | 在己方底线第0列放兵，直接确认；列从0到5 |
| resign | 当前行动方认输 |
| restart | 使用相同种子重开 |
| quit | 关闭电脑程序 |

如果该方向无可行动士兵，允许数量0，仅移动数字；有可行动士兵时不能用0绕过选择。
R/B后的数字是士兵血量，单独的数字是数字块。每次均显示CURRENT STATE；PREVIEW ONLY不是已执行。
先输入w 1，再cancel，棋盘应不变；再输入w 1和ok，应换为蓝方。试完反馈规则是否符合预期。

## 第一版边界

默认6×6、血量8攻击2、放兵4金币、合并奖励1、击杀敌兵奖励2；数字先、士兵后。
数字伤害发生在压缩与合并完成后。数字达到65536后不再合并，金币上限1000000，防止数值溢出。
可行动友兵链按方向从前往后处理，但未选中的前兵不会自动移动。
指示点暂用边中心，数量键盘输入；未实现角度/滞回、放置模式的倾斜选列、音效、LVGL、AI或蓝牙。
预览为调试用途显示完整候选后状态，包括下一随机数字；正式UI应隐藏未来随机信息。
预览结构只供同一可信进程使用，不可把它当作蓝牙输入直接提交；联机应提交行动意图由房主重算。
API当前单线程调用，gy_selftest为启动专用、不可并发重入。
板端仍是RGB例程加核心自检，烧录它不会出现游戏棋盘。本轮没有烧录或硬件验证。

## 代码理解顺序

### 新增输入层

geyi_input.c现在接受模拟角度、毫秒时间及按键电平，并输出选择/取消/确认事件。
5ms时间序列测试覆盖方向、稳定200ms、20ms键消抖、长按、回中、断流及时间回绕。
它尚未读取板上IMU，也尚未连接CLI或LVGL；play-single.cmd的操作没有变化。
所以目前不是“倾斜板子就能走棋”。真实数据需要先校准并映射到屏幕坐标。

调用顺序：gy_eligible_count计算每个方向可行动兵数 → gy_input_update处理样本 →
SELECT生成gy_preview → CANCEL撤销预览 → CONFIRM调用gy_commit；棋盘版本变更后重置输入。
gy_input_reset后首次需回中，避免开机拿起板子就误触。
