## 摘要

截至 2026-11-10，格弈的单机、人机、参数页、规则页与 BLE 联机主流程已完成，学生本人在真机上确认倾斜、走字、进出房间、旁观与断线重连正常。学生确认的是重构前 1,093,852 B 固件；随后完成的清理重构产出 1,091,788 B + LCPU 6,384 B，主机 24,572/105/283/2517/85/59/10 + 联机 428/358 断言、双板完整套件、三端旁观套件与 `net_input_test` 输入注入全部通过，学生确认重构后功能完好、可以提交。

主机侧的核心结论是：输入延迟由 200 ms 稳定窗口主导，采样率从 1 ms 提到 20 ms 只增加约 19 ms；Alpha-Beta 在深度 5 把节点数从 13,078 降到 607（−95.4%），主机耗时从 60.4 ms 降到 3.2 ms；联机关键时延从修复前的 4.07 s/3.66 s 降到 0.90 s/0.18 s；平衡扫描在 500 局样本下红方总体胜率 56.9%，只有参数组 15/19 仍高于 72%。主机覆盖率 76.5%–100%，全部高于 70% 门槛。

固件体积为 1,091,788 B（1.041 MiB），低于范围变更后重新基线化的 1.5 MiB 资源目标。主要增量来自 BLE/联机与协议栈（含 LCPU 镜像）；中文字体子集扩到 281 字形也有贡献，但量级较小。板载 16 MB NOR 容量充足，功能不受影响。仍缺的验收项是仪器量化、24 h soak、BLE 容量 P-02、房主掉电/精确 10 s、参数板端生效、历史/计时与新用户试玩。

**架构根因**：BLE `conn_idx` 会被快速复用，而 App 只按 `conn_idx` 找 ConnMap；链路断开、
新连接建立、旧包迟到三件事没有“代际”概念。客户端离开时若连接还在途，没有取消手段，
会留下没有应用会话的链路，房主因连接态停止可连接广播，房间从大厅消失。旧代码还把
“离房”做成 UI 线程阻塞式 flush，放大卡顿观感。修复见 `docs/02` 第六轮设计小节。

**第六轮独立 review 后的追加修正（2026-11-09）**：

独立 agent 逐条审查了链路生命周期、TX/RX/UI 线程边界、REJOIN 与广播状态机，指出
并修复以下问题（P1/P2）：

- **异步离房→立刻进新房**：`client_leave` 后旧链路尚未断开时，`gy_net_ble_ready()`
  仍为真，新房间的 JOIN 可能被发到旧房主（room_id 不符被拒，表现为“房间不存在”）。
  修复：`ready()` 要求 `g_mode==2 && !g_client_leaving`；`join_index_role` 进新房间前
  强制 `client_abort()` 并清 `g.leaving`；`gy_net_ble_send` 在离房态直接拒绝。
- **旧 LEAVE 的断开按 conn_idx 执行**：可能拆掉复用同一序号的新链路。TX 项携带入队
  时的 gen，新增 `disconnect_if_gen()`，只有当前链路 gen 仍匹配才断开；`client_leave`
  先清空旧会话未发消息，再入队 LEAVE。
- **REJOIN 只发一次**：REJOIN 丢包后客方永不再发，10s 后误显示“对方断线”。改为
  500ms 重发；每次新 gen/链路断开清 `rejoin_sent`；房主对“同链路同 token 的重复
  REJOIN”幂等回 ACK，不再回 TOKEN 拒绝；REJOIN 不得抢占同一 conn_idx 上 live token
  的 ConnMap。
- **满员广播无恢复路径**：`connectable=0` 时 advertising 停止后不再安排重启，满员房间
  会从大厅消失。改为只要 `g_mode==1 && g_adv_inited` 就按当前 mode 重启广播。
- **ConnMap 槽位/连接表溢出**：`conn_alloc` 不再驱逐仍持有 live token 的映射；BLE 第 5
  条连接（`conn_alloc` 失败）立即断开，避免应用看不见的僵尸链路。
- **房主接管未清 client 会话**：`promote_self_to_host` 先 `client_abort()` 再
  `host_start`，旧 client 消息不会被当成 host 广播。
- **旁观者房主丢失**：直接 `active=0` 改为先 `client_abort()`，不再留链路到超时。
- **测试加强**：`pc_ble_peer.py` 的 idle-link 断言改为“本次新增日志包含 drop idle
  link 且 PC 端确认断开”，不再用历史全文；edge churn 仍保留。

复测：主机 307 + app 254 PASS；双板完整套件 PASS；latency join **0.98s**、leave
**0.35s**、close **0.41s**；PC 三场景（third-peer/idle-link/burst）再次 PASS。证据
`board_suite_review_final.log`、`latency_after_review_fix.log`、
`pc_ble_third_peer_review.log`、`host_test_review_fix.log`。

**未验证**：真实触摸下的“加入后立刻返回”仍建议学生复测；10s 静默断开/槽位耗尽的
故障注入未做；广播 shadow state 与 BLE 事件线程仍未加锁（P3）；房主主动离房仍有约
350ms UI 阻塞；第三块实体板/手机兼容性、双旁观者、P-02 容量未测。

1. 旧语义把 WAIT 断线当“立即释放”，无法等重连；改为链路断开保留席位 10s，
