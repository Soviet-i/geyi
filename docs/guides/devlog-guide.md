# 开发日志规范

## 为什么写

日志是你自己的“工作证明”和复盘素材：几周后你需要靠它写研制总结，教师需要靠它判断过程是否真实、你有没有真正参与决策。好日志的标志是：**没参加过的人读完能复现你当天做了什么、为什么这么做。**

## 要求

| 要求 | 说明 |
|---|---|
| 每个有提交的日期必须有日志 | 文件名 `YYYY-MM-DD.md`，位于 `docs/devlog/` |
| 收工前完成 | 补写要在日志中标注“补写”和原因，且仍需基于真实记录 |
| 最少内容 | 有效字数 ≥ 120；「今日完成」≥ 30 字，「AI协作记录」≥ 6 字，「明日计划」≥ 6 字（`course.config.json` 可调整） |
| 如实 | 写做成了什么，也写没做成什么、走了哪些弯路 |
| 与提交对应 | 日志、git 提交、`evidence/` 三者的时间应能对上 |
| 断档说明 | 连续 7 天无提交，在恢复后的第一篇日志里说明原因 |

## 怎么写

```bash
python scripts/new_devlog.py          # 创建；“今日提交”区块会自动从 git 生成
# …开发…
python scripts/new_devlog.py --update # 收工前刷新提交列表
python scripts/check_devlog.py        # 自查
```

### 各小节写什么

- **今日目标**：开工时写 1~3 条，尽量带需求/任务编号（REQ-002、T-03）。
- **今日完成**：产出与结果，不是流水账。写“实现了 X，编译通过，上板串口输出符合预期（evidence/M2/…）”，不要只写“写了代码”。
- **遇到的问题与解决**：现象 → 排查 → 根因 → 办法。有价值的同步登记 `06-风险与问题台账.md`。
- **AI协作记录**：这是评审重点。写清：你问了什么、agent 给了什么、你采纳/修改/否决了什么、你如何验证、agent 出过什么错。
- **物理验证**：做了什么真机验证、结果、证据路径。
- **明日计划**：下一步最具体的 1~3 件事。

## 对比示例

差：

> 今日完成：写了灯的代码，试了一下，没问题。

好：

> 今日完成：让 agent 按 REQ-002 实现 RGB 灯红绿蓝闪烁，编译通过；上板后串口有 red/green/blue 日志但灯不亮（evidence/M2/rgb_dark.jpg）。对照官方 rgb_led 例程发现缺 LDO 使能，让 agent 补上后重新烧录，灯正常（evidence/M2/rgb_ok.txt）。
> 遇到的问题：agent 第一版只检查了 PWM 通道配置，没发现供电问题；我拿官方例程逐行对比才定位到。
> AI协作记录：采纳了颜色表结构；否决了它自作主张加的“呼吸灯渐变”（超出 REQ-002）；agent 出错 1 次（漏 LDO），“编译通过”它说对了，“灯应该会亮”它说错了。

## 用 agent 帮你写日志

可以。Claude Code 里运行 `/devlog`，其他工具把 `docs/guides/agent-collaboration.md` 里的“收工提示词”贴给它。规则：

1. agent 只能依据真实的 git 记录和你的口述起草；
2. **你逐节确认**后才落盘；
3. 不确定的地方它必须问你，不得编造实测数据或你没做过的事。
