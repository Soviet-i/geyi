# ADR-0008: 联机断线与重连策略

- 状态：已采纳
- 日期：2026-11-08
- 决策人：蔡融汉　协助：Claude Code / deepseek-v4-flash
- 关联需求：REQ-508、REQ-509、REQ-510、REQ-511

## 背景

BLE 链路会瞬断，不能把一次 BLE 断开直接当成玩家认输。联机需要一套应用层判活与
重连规则，覆盖客方、房主、旁观者三种角色，并明确“谁判谁负”、窗口多长、重连后
如何恢复。若不先定，断线时序会在编码时变成竞态和争议判罚。

## 备选方案

| 方案 | 优点 | 缺点 | 对需求/风险的影响 |
|---|---|---|---|
| A. 应用层心跳 1s + 10s 判连 + 10s 冻结重连窗口 + token REJOIN + 全量快照恢复 | 能区分瞬断与真掉线；窗口内不误判；token 绑定席位；恢复直接 | 需要心跳/定时器/冻结 UI；实现和测试复杂度上升 | 满足 REQ-508~511；竞态见 R-025 |
| B. 立即判负（BLE 断开即输） | 实现最简单 | 瞬断、信号抖动会误判；体验差；无法重连 | 不选 |
| C. 无限等待，直到对方回来 | 不会误判 | 对局可能永久卡住；房主/客方都无法收尾 | 不选 |
| D. 只依赖 BLE 链路监督超时 | 不用自己写心跳 | 超时时间不可控/因平台而异；不能覆盖应用层卡死；难以做统一判据 | 不选 |
| E. 断线后新开一局/新会话 | 状态简单 | 丢失当前对局；与“重连继续”需求不符 | 首版不选 |

## 决策

选择 **方案 A**：

- 应用层心跳 1s（房主 `HEARTBEAT`，客方 `PING`）；10s 无包判断连，不依赖 BLE 链路监督超时。
- 断连后进入 10s 重连窗口：对局冻结，显示“重连中 10…9…”；窗口内不判负。
- 客方保存 `{房主地址, roomId, 会话 token, 最后 seq}`；重连发 `REJOIN(token,last_seq)`，
  房主校验席位与 token 后回全量快照，继续对局；token 在房间存续期内有效。
- 房主掉线：客方重试连接 10s；超时显示本地终局提示（非权威 RESULT）。
- 旁观者掉线：不冻结对局；10s 内可重连拿快照，超时回大厅提示“已离开旁观”。
- 主动退出 ≠ 断线：对局中“退出”二次确认后立即判负；等待阶段退出只释放席位。
- **2026-11-09 修订**：WAIT 阶段没有可恢复的对局，客方/旁观者断线或退出**立即释放席位**
  并广播，不进入 10s REJOIN 窗口；10s 窗口只适用于 PLAYING。房主通知丢失时，
  客方仅在 BLE 链路确实断开 2.5s 后接管（两玩家房），链路仍通时用 fresh JOIN 重新入座，
  避免双房主。
- 判定责任：在场方判缺席方负；旁观者只显示房主广播结果或本地断线提示。
- 结算后房间保留约 10s 供重连者看结果；房主返回大厅即解散。

理由：10s 足够覆盖常见 BLE 瞬断，又不会让对局无限卡住；token 让重连绑定原席位，
避免“随便一个人重连就占位”；全量快照让恢复不需要补发增量。房主单点按 L-07 不做迁移，
对局期房主丢失由客方超时判负，是明确的代价。

## 后果

- 正面：瞬断不误判；重连有明确时限和判据；三种角色行为可写成主机状态机测试。
- 负面/代价：需要心跳、冻结 UI、定时器和 token；断线/重连竞态需要专门测试（R-025）；
  房主掉线时客方体验是本地终局提示而非续局（不是权威 RESULT）。
- 需要同步修改：`docs/01` REQ-508~511；`docs/02` 联机设计；`docs/03` TC-508~511；
  `manifest.yaml` 的 `design.key_decisions`。

## 待实测/待定

- 实际 BLE 断开到应用层心跳超时的时延；10s 窗口是否足够（可在实测后调整，但需记录需求变更）。
- 重连时 BLE 地址/隐私地址是否稳定；roomId 与 token 的生成方式。
- 等待阶段房主退出时，token/席位/颜色如何转移（R-029）。

## AI协作

agent 根据学生方案整理 A~E 备选；学生明确选择“1s 心跳 + 10s 判连/冻结 + token REJOIN +
在场方判缺席方负”。agent 补充了“不依赖 BLE 链路监督超时”和“旁观者不冻结”的边界，
均来自学生方案；未自行增加局内房主迁移。
