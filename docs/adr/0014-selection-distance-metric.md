# ADR-0014：选兵距离度量为“到方位边指示点的欧氏距离”

- 状态：已采纳（学生 2026-11-13 选择“加权距离”）
- 日期：2026-11-13
- 决策人：项目负责人（本次会话明确选择）
- 关联需求：REQ-320-B
- 关联问题：R-081

## 背景

REQ-320 引入 `aim` 后，选兵排序实现为“先横向、再深度”的字典序：

```c
distance = lateral * (2 * GY_MAX + 2) + depth;   /* 权重 18 */
```

`GY_MAX=8` 时，权重 18 大于整条深度轴的最大值 15；横向相差一格（双倍坐标差 2，
36 分）就压过纵向走满整个棋盘的差距。因此只要某颗棋子所在列更靠近方位线，它无论
离目的边多远都会先动。

学生 2026-11-13 的截图（8×8，执蓝，向正下方倾斜，`aim≈0`、`count=1`）：

- B6 在上方偏中列：横向差约 4 个半格，深度约 9~11；
- B8 在下方偏左列：横向差约 6 个半格，深度约 3~5；
- 旧公式得分 81~83 vs 111~113，结果 **上方的 B6 先动**，与“离倾斜方向最近的棋子
  先动”的规则页文案和玩家预期冲突。

这不是实现笔误：`docs/02` 与 `tests/test_geyi.c` 都明确写的是“方位优先于深度”。
但该规则在 8×8 大棋盘上会让“方位列”完全压过“离目的边远近”，需要重新定义。

## 备选

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 保持“横向优先、深度次之” | 完全符合旧 REQ-320-B 与旧测试；改动为零 | 学生截图中的现象是规则直接结果；大棋盘上“最近的兵”几乎不起作用 |
| B. 深度优先，横向做并列判据 | 最贴近“离倾斜方向最近”；实现简单 | 方位在绝大多数情况下只做同深度并列，`aim` 的选择作用很弱 |
| C. 到方位边指示点的欧氏距离（平方后比较） | 同时考虑“离目的边多近”和“离倾斜方位多近”；截图局面 B8 先动；同行左右选择仍由 aim 决定 | 需要更新 REQ-320-B、设计、测试与旧断言；不同局面的手感需真机确认 |
| D. 只改规则页文案，保持代码 | 零回归风险 | 玩家看到的行为与文案仍不一致，问题不解决 |

## 决策

采用 **C：按可行动士兵到“方位边指示点”的欧氏距离排序**。

- 指示点仍由 `aim` 决定：方向边中点 ± `aim` 比例（现有 `aim_point()` 不变）。
- 比较时使用双倍格坐标的平方距离，避免开方与浮点：

```c
distance = lateral * lateral + depth * depth;
```

- 距离相同（例如偶数尺寸、两个兵关于指示点对称）时保持扫描顺序（先行后列）。
- `lateral`、`depth` 仍按方向取双倍格坐标，与现有 `aim_point()` 一致。
- 可行动集合、数量上限、`move_pass()` 的遍历顺序不变；只改“选哪 N 个”。

## 后果

- 截图局面：B6 ≈ 4²+11²=137，B8 ≈ 6²+3²=45，B8 先动。
- REQ-320-B 原有的“底行左/中两兵”同行例子仍成立：深度相同，横向距离决定左右。
- 旧测试“方位优先于深度：后排左兵优先于更靠前的中间兵”会失败，需按新规则改写，
  并保留旧规则失败记录；新增 8×8 正下方截图回归用例。
- 需要同步 `docs/01/02/03`、`docs/06` R-081、`tests/test_geyi.c` 与 `manifest.yaml`。
- AI 的走法空间不变，但排序结果会变化，需重跑主机 AI 自对弈与平衡扫描，确认无回归。
- 真机倾斜手感（尤其 8×8、数量 >1、斜向）必须由学生复测并回传证据；编译/主机
  PASS 不等于物理验收。
