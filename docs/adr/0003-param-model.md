# 参数模型与校验策略

日期：2026-10-17。状态：提案（待组长确认范围与取值后定稿）。

10 项游戏参数要同时被**规则、倾斜输入、AI、配置界面、主机测试**五处读取，且需支持三类分类、
重置、越界拒绝。需要先决定参数怎么组织。

备选 A：显式结构体字段 + 一张只读范围表；B：通用键值数组（字符串键 + 运行时查找）；
C：把取值直接散落在各自的界面回调和规则里。

**选 A。** A 的代价是新增参数要改结构体；换来的是编译期类型检查、没有字符串键拼写错误、
主机测试可以直接断言字段值、界面按同一张表渲染即可，校验与界面不会各写一套判据。
B 更灵活，但对一个固定的小集合引入字符串键与运行时查找，测试只能断言"键存在"而不是"字段值"，
收益低于复杂度。C 正是要避免的：判据分散后，界面允许的值与规则接受的值会慢慢分叉。

**暂不持久化。** 参数存 RAM，重启回默认。代价是用户调整在掉电后丢失；
收益是不引入 Flash/TF 卡依赖、不承担掉电写入损坏风险，而 REQ-401~411 的验收判据均不要求跨重启保留。
若后续确需持久化，另开 ADR 评估存储占用与写入寿命，不在本轮范围。

**取值范围的依据**（《想法》稿只要求"设限制"，数值由本模块建议）：

- 棋盘 4~8：默认 6；下限 4 保证开局（2 兵 + 2 数字）后仍有可行动空间；
  上限 8 受 390×450 屏幕上单格尺寸与血量条可读性约束，**需实现后实测确认**。
- AI 搜索深度 1~6：默认 3；上限用于避免 AI 思考过久，**具体耗时需实测后可能下调**。
- 生成间隔（奇数 1~9）：默认 1；间隔过大时数字单位过少，玩法会退化为纯战棋。
- 倾斜方向/角度缓冲（0~50%）：默认 10%（与改造前硬编码一致）；
  0% 表示无滞回，50% 表示滞回达到半个区间上限，再大将无法切换。

**回归保护**：新增 4 项默认值一律取**改造前的硬编码值**，使改造前后行为一致，
可用现有 TC-301~308 做回归对照，避免参数化本身引入行为变化。

**AI协作**：备选与权衡由 agent 提出；"用显式结构体而非键值数组"与"v1 不持久化"两项取舍由学生确认；
取值依据中标注"需实测确认"的两项由 agent 主动标注为未验证，不得当作已测结论。
