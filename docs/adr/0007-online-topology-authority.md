# ADR-0007: 联机拓扑与权威模型

- 状态：已采纳
- 日期：2026-11-08
- 决策人：蔡融汉　协助：Claude Code / deepseek-v4-flash
- 关联需求：REQ-501、REQ-502、REQ-503、REQ-506、REQ-512

## 背景

格弈要在两块黄山派 SF32LB52 开发板之间做联机对战。硬件约束是板载无 WiFi，
只能走蓝牙/BLE；课程板卡稀缺，两块板同时在线的时间有限（R-021）。联机还需要
大厅发现、房间准备、对局同步、旁观和断线恢复。必须先决定：

1. 谁做 BLE 外设/服务端，谁做中央设备；
2. 对局状态由谁权威计算，客户端是否本地提交；
3. 同步用全量快照还是增量动作。

这些决定会同时影响协议、线程模型、断线恢复和作弊边界，不能等到编码时再临时定。

## 备选方案

| 方案 | 优点 | 缺点 | 对需求/风险的影响 |
|---|---|---|---|
| A. 房主 BLE 外设 + GATT 服务端 + 房主权威 + 全量快照；对手/旁观者为中央，只发意图 | 房主是唯一裁判，随机块只由房主生成；客户端不本地提交，状态分叉风险低；断线后直接发全量快照即可恢复；多房间=多房主，不需要服务器 | 房主是单点，房主掉线整局受影响；全量快照有带宽开销；房主要承担校验和广播 | 满足 REQ-501/506/512；房主单点见 L-07；快照带宽见 R-026 |
| B. 双端锁步：两端各跑规则，只同步动作和随机种子 | 带宽小；两端都有完整状态 | 需要严格确定性、同版本、同随机序列；任何一端卡顿/丢失都会分叉；作弊边界弱；断线恢复复杂 | 实现和调试成本高；不选 |
| C. 房主权威 + 增量动作/差分同步 | 带宽比全量小 | 需要差分编码、基线确认、丢包重传；断线恢复仍需全量快照；6×6 规模收益有限 | 复杂度高于收益；首版不选 |
| D. 所有端都做 BLE 中央，经手机/中继转发 | 可能绕开连接数限制 | 需要额外设备和软件；增加单点与延迟；课程范围外 | 不作为首版 |

## 决策

选择 **方案 A**：房主同时充当 BLE 外设、GATT 服务端与唯一裁判；对手和旁观者都是
连接房主的 BLE 中央设备；客户端只发操作意图，房主用现有 `gy_preview`/`gy_commit`/
`gy_place` 结算，每个合法动作后广播带单调 `seq` 的全量快照；客户端只认最新 `seq`，
不本地提交落子。预览只作为本地临时状态，按 REQ-507 单独路由。

理由：联机首版最重要的是**状态一致和可恢复**，不是极限省带宽。6×6 棋盘的全量快照
体积可控，换来房主唯一裁判、随机块唯一来源、断线后一发快照即可恢复；同时避免双端
锁步对确定性和时钟的严格要求。房主单点的代价已知，按 L-07 约定：对局期不做房主迁移，
房主掉线由客方在 10s 后判负；等待期房主退出按 REQ-505 转移或关房。

## 后果

- 正面：规则只在房主执行；客户端无法通过本地提交制造分叉；断线恢复简单；大厅/多房间
  不需要中心服务器；旁观者天然是只读镜像。
- 负面/代价：房主是单点；房主需要校验每个意图并广播快照；全量快照的包长/频率需要
  实测（R-026）；房主等待期退出要实现席位/颜色/token 转移（R-029）。
- 需要同步修改：`docs/01` REQ-501/502/503/506/512；`docs/02` 联机设计；
  `docs/03` TC-501/502/503/506/512；`manifest.yaml` 的 `design.key_decisions`。

## 待实测/待定

- P-02 房主最大 BLE 并发连接数；连接态能否继续广播；若只能 1 条连接，首版砍旁观或中继。
- 全量快照在 BLE MTU 下的分包、延迟与丢包表现。
- roomId 生成、BLE 地址稳定性/隐私地址对重连的影响。
