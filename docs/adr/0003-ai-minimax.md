# 人机对战采用 Minimax + Alpha-Beta

日期：2026-10-17。状态：已采纳（学生选择），实现与真机验证待完成。

## 背景

想法稿要求人机对战使用“含 Alpha-Beta 剪枝的 Minimax 算法”，并录视频对比
不含剪枝的 Minimax。当前单机原型已有纯 C 规则核心、LVGL 界面、倾斜输入和
板端接入，需要在模式页开放人机对战。

## 决策

- 使用 **negamax + Alpha-Beta**（与 Minimax 等价），另保留 `use_pruning=0`
  的全量搜索用于性能对比。
- 搜索 **不建模每步随机生成的 2/4 数字块**：新增
  `gy_simulate_move(..., spawn_next=0)`，搜索只做走子/合并/伤害/胜负和换手，
  不读取真实 RNG；真实落子仍由游戏自身 RNG 生成。
- 开发板上 AI 运行在 **独立线程**，主线程传快照并轮询结果，保证 LVGL 可刷新、
  首页/重开可取消。
- 模式页提供 **“人机对战（我执红）/（我执蓝）”两个按钮**，人类执红时先手，
  人类执蓝时 AI 执红先手。
  > 入口方案后被 ADR-0004（单入口 + 先后手准备页）取代；AI 算法、搜索和线程决策不变。
- 默认迭代加深最多 5 层，单次 300ms、节点数上限 200000；超时保留上一层最佳
  着法。自定义搜索深度页本轮不实现。
- 规则 PDF 与个人 `minimax.md` 原件留在课程资料目录，仓库只保存摘要和评估
  笔记（`docs/refs/`），不把课程 PDF 复制进公开仓库。

## 考虑过的备选

| 备选 | 放弃原因 |
|---|---|
| MCTS/UCT | 分支本来不大；大量模拟对板端 CPU/内存压力大，结果不稳定、难复现，且不符合想法稿要求 |
| 完整 Expectimax | 机会节点分支为“空格 × 2”，板端深度和耗时压力大；本轮先按学生选择不建模随机块 |
| 纯规则/启发式 AI | 快但短视，无法展示搜索和剪枝性能 |
| 搜索读取真实 RNG（`preview.after`） | 等于偷看下一步随机块，不公平，且测试随种子变化 |
| 主线程阻塞搜索 | 实现简单但会冻结 LVGL，想法稿要求在 AI 思考时可退出 |

## 后果

- 搜索中的数字块数量会比真实对局少（每步少一个新生块），评估可能略低估
  数字块威胁；这是已知近似，记录在风险台账 R-010。
- 独立线程需要额外栈和同步；板端内存/耗时必须在真机上测量，不能以主机结果
  代替。
- 评估权重是初始值，需用固定局面和自对弈调参；不代表平衡性已经通过。
- 需要保证 `gy_simulate_move(...,1)` 与 `gy_preview` 的 `after` 行为一致，
  避免重构改变现有规则；用核心回归测试覆盖。

## 2026-10-28 实现备注（待学生确认）

- REQ-405 把参数页的搜索深度范围定为 1~6，而本 ADR 原记录为最多 5 层。
  参数页开放后，`GY_AI_MAX_DEPTH` 调整为 6，使界面设置能真正生效；默认参数仍为
  3 层，AI 启动时读取人机模式的 `search_depth`。
- 这是实现与需求范围的冲突消解，不改变“迭代加深 + Alpha-Beta + 独立线程”的
  原决策。若团队坚持 5 层，应把 REQ-405 改为 1~5 或限制界面选项，并同步
  docs/01/02/03/04；在确认前不把 6 层写成最终产品决策。
