# 入门训练

在动手做自己的产品之前，用两个任务把**整套协作方式**走一遍：先装好环境、体验提交规范（T0），再用一个小功能完整走一遍“需求 → 设计 → 实现 → 测试 → 总结”（T1）。做完你就清楚本课程“怎么做、怎么留证”，自己的产品项目只是把 T1 的流程再走一遍。

## 路线图

| 任务 | 主题 | 预计时长 | 你将练到 | 自动可检查的完成标志 |
|---|---|---|---|---|
| [T0 环境与仓库](T0-环境与仓库.md) | 装 SDK v2.5.1、编译烧录内置例程（RGB 闪烁）、初始化、体验钩子、第一篇日志 | 2.5h | SDK 环境、板级编译烧录、提交规范钩子、日志 | `check_env.py` 必需项全 ✓；`build_firmware.py` 成功；`check_commit_msg.py --log` 全部合规；存在 ≥1 篇有效日志 |
| [T1 完整流程示例：按键切换 RGB 灯](T1-完整流程示例-按键切换RGB灯.md) | 需求→设计（含 ADR）→实现→测试→总结，全程 agent 协作 | 5～6h | 文档先行、agent 协作与把关、物理验证暂停协议、如实记录、研制总结 | `check_trace.py --final` 通过；有 `T1-done` 标签；`docs/04` 与 `evidence/T1/` 对应 |

两个任务都**必做**，T1 必须使用 AI agent 协助完成，并在开发日志“AI协作记录”中如实记录。

## 流程与文档的对应

```
需求   docs/01  →  设计 docs/02 + adr/  →  实现 src/  →  测试 docs/03 + docs/04 + evidence/  →  总结 docs/05.docx
  └──────────── 全程：小步提交（规范）+ 每日开发日志 + 追踪（check_trace） ────────────┘
```

## 通用规则

1. 每个任务开始前新建分支（T0 除外），完成后合并回 `main`。
2. 小步提交，一个提交只做一件事；写当天开发日志。
3. 在 `progress.md` 里登记完成情况（日期、关键提交哈希、自评与遇到的问题）。
4. 需求或验收标准变更要走文档变更记录；**不得为了“通过”事后放宽判据**。
5. 提交前运行 `python scripts/check_all.py`，编译用 `python scripts/build_firmware.py`，把输出贴进日志。

## 没有开发板怎么办

T0 之后的任务以“编译 + 真机观察”收尾。没有开发板时：文档、设计、实现、编译照常完成；所有需要真机的用例在测试报告里标“未执行：无开发板”（不得标“通过”），在 `manifest.yaml` 的 `known_issues` 登记，并把补做计划写进 `docs/06`。这不扣分；编造现象或日志按学术诚信处理。

## 训练的评价要点（教师/评审 agent 依据）

| 维度 | 看什么 |
|---|---|
| 过程真实 | 提交历史是否小步、时间分布是否合理；日志与提交能否对应 |
| 把关能力 | 你是否发现并记录了 agent 的错误；是否否决过越界实现 |
| 规范性 | 提交信息、文档编号、追踪是否闭合；文档是否先于实现 |
| 证据 | `evidence/` 与 `manifest.yaml`、`docs/04` 是否真实对应；失败是否被保留 |
